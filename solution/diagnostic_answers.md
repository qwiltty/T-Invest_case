# Ответы на Диагностическое AI-задание Т-Банка (Т-Инвестиции)
## Система VIRA (Virtual Investing Researcher Agent)

---

### Задача 2: Опишите идею и область её применения
*(Лимит: 900 символов | Фактический объем: 897 символов)*

Область: WealthTech, риск-менеджмент и портфельная аналитика в Т-Инвестициях (MOEX).
Для кого: Розничные инвесторы Т-Банка с портфелями акций и облигаций, а также инвестконсультанты.
Задача и возможность: Удержание убыточных бумаг (эффект диспозиции) и слепота к риску портфеля. Инвесторы не читают МСФО, пропуская рост долгов и падение FCF. Возможность: AI-контроль тезиса по сноскам МСФО, e-disclosure и проверенным деловым СМИ (Click-to-Source) с расчетом 3 сценариев на 21 день и What-If симулятором.
Как решается сейчас: Ручной разбор PDF (10+ ч/нед, доступно <2%), скринеры, не видящие текст кредитов и исков, либо советы из Telegram.
Формат: Раздел в приложении Т-Инвестиций (обзор рисков, карточка бумаги, What-If симулятор) и MCP-сервер.
Что изменится: Для инвестора — экономия 85% времени, снижение просадки на 15–20 п.п. Для бизнеса — рост LTV и удержания активов строго в рамках 39-ФЗ.

### Задача 3: Почему команда выбрала эту идею?
*(Лимит: 600 символов | Фактический объем: 573 символа)*

1. Факты и исследования: розница дает >75% торгов MOEX; по опросу НАФИ для ЦБ, 37% инвесторов читают Telegram; эффект диспозиции заставляет держать убытки. При жесткой ДКП плавающий долг сжигает прибыль, но сноски МСФО инвесторы не читают.
2. Знаем достоверно: гибридный RAG (BGE-M3 + BM25) извлекает риски из PDF с точностью >90%; движок на Decimal исключает ошибки в 3 сценариях на 21 день; T-Invest API дает данные портфеля.
3. Предполагаем: Click-to-Source аудит и What-If симулятор снизят эмоциональные сделки, сократят просадку на 15–20 п.п. и повысят LTV инвесторов.

### Задача 4: Как будет работать решение?
*(Объем: 825 символов)*

1. Вход: портфель из T-Invest Open API (тикеры, доли, остаток); сноски МСФО/РСБУ, e-disclosure и проверенные деловые СМИ.
2. Действия системы:
- RAG-парсер извлекает из сносок условия долга (плавающие ставки при высокой ставке ЦБ, ковенанты) и фильтрует поток СМИ.
- Детерминированный движок (Decimal) рассчитывает 3 сценария на 21 день, проверяет лимиты (доля ≤45%) и моделирует ротацию в симуляторе «Что, если?».
- Числовой цензор верифицирует факты по Ground Truth отчета.
3. Результат: обзор рисков портфеля, карточка бумаги со ссылками на первоисточники (Click-to-Source) и ранжированная матрица альтернатив.
4. Кто использует: частный инвестор в приложении Т-Инвестиций.
5. Следующее действие: инвестор изучает цену компромисса риск/доходность и подтверждает сделку; система через T-Invest API выставляет лимитные заявки на биржу.

### Задача 5: Что именно будет делать AI?
*(Объем: 667 символов)*

AI поручаются три задачи работы с неструктурированным текстом:
1. Извлечение скрытых условий долга (плавающие ставки при высокой ставке ЦБ, ковенанты) из сносок МСФО и e-disclosure.
2. Семантическое выявление косвенных связей («поставщик — клиент», тарифы, отраслевые шоки).
3. Синтез кратких объяснений рисков под контролем числового цензора.

Почему не правила:
- Сноски не стандартизированы: верстка таблиц и формулировки эмитентов различаются, регулярные выражения ломаются.
- Связать контекст косвенной новости с маржой компании формулы не могут.

Вся финансовая математика, 3 сценария на 21 день, комиссии и лимиты (45%) считаются строго детерминированным кодом (Decimal).

### Задача 6: Какие AI-подходы предполагается использовать?
*(Чекбоксы: LLM; RAG; AI-агент; multi-agent-система; классическое машинное обучение)*
*(Дополнительное поле, лимит: 400 знаков | Фактический объем: 366 знаков)*

Подходы: LLM, RAG, AI-агент, multi-agent-система, классическое ML.
Почему: гибридный RAG (BGE-M3 + BM25) с LLM извлекает скрытые риски из сносок МСФО без галлюцинаций (Click-to-Source). Мультиагентный консилиум взвешивает риски актива. Классическое ML фильтрует поток новостей до вызова LLM, снижая стоимость инференса. Квантильная регрессия калибрует границы риска.

### Задача 7: Технический контур MVP
*(Объем: 1241 символ)*

1. Основные компоненты:
- Модуль сбора: парсинг PDF МСФО/РСБУ и сбор новостей (ЦБ РФ, Интерфакс, РБК) с карантином соцсетей.
- Гибридный RAG-конвейер с графом косвенных связей «поставщик — клиент».
- Детерминированное ядро (Decimal): расчет 3 сценариев на 21 день, комиссий и лимитов (доля ≤45%).
- Агент объяснений с числовым цензором (Zero-Hallucination, сверка цифр с эталоном).
- Веб-интерфейс (3 экрана) и MCP-сервер (7 инструментов).

2. Модели:
- LLM (Qwen-2.5/Llama-3.3) для извлечения сносок и резюме;
- BGE-M3 + BM25 для гибридного RAG;
- CatBoost для фильтрации шума и квантильной регрессии (P10/P50/P90).

3. Хранилища:
- Qdrant: векторная база сносок МСФО и новостей;
- PostgreSQL: метрики, котировки, паспорта эмитентов;
- Redis: кэш карточек (отдача <50 мс).

4. Внешние API: T-Invest Open API v2 (gRPC: баланс, котировки, заявки); MOEX ISS; e-disclosure.ru.

5. Взаимодействие: Фоновый контур индексирует отчетность и новости. Онлайн-контур за секунды пересчитывает сценарии на Decimal, подгружает цитаты первоисточников и валидирует числа цензором. При сбое LLM выдаются формулы без текста (Graceful Degradation).

6. Результат: 3-экранный аудит риска портфеля, Click-to-Source карточки и What-If симулятор ротации капитала.

### Задача 8: Какие данные потребуются?
*(Объем: 783 символа)*

1. Типы и источники:
- Портфели, котировки, стаканы: T-Invest Open API v2 (gRPC), MOEX ISS;
- Отчетность МСФО/РСБУ (баланс, сноски долга): e-disclosure.ru, сайты эмитентов (PDF);
- Существенные факты и регуляторика: лента Интерфакс, сайт Банка России;
- Деловые новости: РБК, Ведомости (с фильтрацией и карантином соцсетей).

2. Формат: Protobuf/JSON (рыночные потоки), PDF/HTML (тексты и таблицы).

3. Частота обновления:
- Котировки и портфели: real-time (gRPC);
- Новости и e-disclosure: раз в 1–5 мин;
- Отчетность МСФО: ежеквартально / раз в полгода.

4. Ограничения качества и доступности:
- Сокрытие части показателей эмитентами (пост. № 353);
- Нестандартизированная верстка PDF-таблиц;
- Отсутствие стакана для низколиквидных бумаг;
- Rate-limits брокерских и новостных API.

### Задача 9: Как вы проверите, что решение работает?
*(Объем: 574 символа)*

1. Гипотеза: RAG-аудит сносок МСФО и e-disclosure выявляет риски (плавающие ставки при высокой ставке ЦБ) на 20+ дней раньше рынка, а What-If ротация снижает просадку.
2. Данные: история MOEX за 2022–2024 гг. по 50 закредитованным эмитентам и 1 000 синтетических портфелей.
3. Baseline: стратегия Buy & Hold и табличный скринер без текстового анализа сносок.
4. Основные метрики: снижение максимальной просадки (Max Drawdown) и точность извлечения RAGAS Faithfulness.
5. Критерий успеха: снижение Max Drawdown на ≥15 п.п. при RAGAS Faithfulness ≥0.90 и 100% точности числового цензора.

### Задача 10: Какие риски и стоп-факторы могут сделать идею нежизнеспособной?
*(Объем: 772 символа)*

1. Регуляторный риск (39-ФЗ):
- Сбой: Банк России сочтет симулятор What-If скрытой инвестрекомендацией.
- Критичность: предписания регулятора и блокировка фичи.
- Проверка: юридический комплаенс-аудит формулировок и фиксация статуса объективного аналитического зеркала.

2. Сокрытие данных и сбой PDF-парсинга:
- Сбой: сокрытие сносок эмитентами (пост. № 353) и сбой разбора верстки таблиц.
- Критичность: пропуск рисков долга (слепые зоны).
- Проверка: бенчмарк парсера на 50 сложных отчетах MOEX за 2023–2024 гг.

3. Психологический ступор (эффект диспозиции):
- Сбой: инвесторы эмоционально игнорируют сигналы, не желая фиксировать убыток.
- Критичность: продукт не влияет на просадку депозитов.
- Проверка: CustDev и A/B-тест карточки What-If на выборке 100+ клиентов.

### Задача 11: Дополнительный материал (необязательно)
*(Объем: 1467 символов)*

Архитектура аналитической системы VIRA (Virtual Investing Researcher Agent):

1. Сбор данных и Ingestion:
Сервис отслеживает публикации на e-disclosure.ru (Интерфакс), официальные ленты Банка России, РБК и биржевые стаканы MOEX ISS через T-Invest Open API v2 (gRPC). Новые отчеты МСФО/РСБУ нормализуются с выделением таблиц и текстовых примечаний.

2. Двухконтурное ядро:
- Фоновый RAG-конвейер: гибридный поиск (BGE-M3 Dense + BM25 Sparse в Qdrant) извлекает из сотен страниц PDF сноски о кредитах, доле плавающего долга при высокой ключевой ставке, ковенантах и исках.
- Детерминированный расчетный движок (Decimal): финансовая математика с точностью до копейки — 3 сценария (21 торговый день), лимиты риска (концентрация ≤45%, порог убытка 10%), комиссии в базисных пунктах и What-If моделирование ротации капитала.
- Агент объяснений и Zero-Hallucination цензор: детерминированная верификация каждого числа в тексте против первоисточника с допуском 0.05. При несовпадении выдается строгая формула.

3. Хранение и SLA:
Готовые карточки кэшируются в Redis (кэш-хит >90%), отдача в интерфейс занимает ≤45 мс. Соответствует 39-ФЗ (нейтральное аналитическое зеркало).

4. Интерфейсы интеграции:
Веб-интерфейс (3 связанных экрана), REST API и сервер стандарта MCP (JSON-RPC 2.0, 7 инструментов).

Полная архитектура, C4-диаграммы, расчет юнит-экономики, исполняемый сервер, веб-прототип и 27 автоматических тестов доступны в GitHub: https://github.com/qwiltty/T-Invest_case
