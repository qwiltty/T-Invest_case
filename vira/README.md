# VIRA — Этап 4 (Кодинг): Веб-MVP и проверяемый расчётный модуль

Реализация первой технической поставки VIRA по материалам этапов 1–3 (`VIRA-Передача-в-разработку.md`, `VIRA-02-Бизнес-анализ.md`, `VIRA-03-Дизайн`).

## Архитектура поставки

- **`vira/data/educational_cases.json`** — машиночитаемые учебные снимки портфелей (`review` UC-03, `topup` UC-01, `partial_data` AC-03.4, `payouts_demo` Q-02), параметры бумаг, предпосылки сценариев, источники и статус свежести данных.
- **`vira/models.py`** — контракты данных и единое детерминированное округление (`Decimal`, `ROUND_HALF_UP` до `0.01`) для расчётов и отображения в UI.
- **`vira/engine.py`** — проверяемый расчётный модуль без UI-зависимостей:
  - 3 сценария на 21 торговую сессию, вклады позиций (`AC-03.2`), дивиденды/купоны и комиссии (`Q-02`, `BR-02`, `BR-07`);
  - пороги светофора `45%` концентрации и `10%` пессимистичного убытка (`Q-03a`, включительно на границах);
  - фильтрация и ранжирование вариантов для UC-03 и UC-01 (`Q-04e`, `BR-12`);
  - интерактивная What-If симуляция частичной продажи и замены за счёт чистой выручки (`UC-05`).
- **`vira/agent.py`** — модуль объяснений агента:
  - режим по умолчанию `rule_based` (детерминированные объяснения по `BR-03`–`BR-12`, `Q-04b`–`Q-04d`);
  - опциональный адаптер `LLMExplainer` (`VIRA_AGENT_MODE=llm` при наличии `OPENAI_API_KEY`);
  - `GuardrailValidator` проверяет каждое числовое утверждение по эталонным значениям расчёта и источников с автоматическим откатом на `rule_based` при расхождении.
- **`vira/mcp_tools.py`** — MCP-совместимые инструменты (`vira_list_portfolios`, `vira_get_overview`, `vira_analyze_asset`, `vira_compare_options`, `vira_simulate_what_if`) и JSON-RPC обработчик (`Q-05a`).
- **`vira/server.py` и `vira/web/`** — HTTP/REST-сервер на стандартной библиотеке Python и веб-интерфейс в стиле дизайна этапа 3, получающий все расчёты и объяснения через `/api/*`.

## Запуск

```bash
# Веб-демо на http://127.0.0.1:8000 (режим бизнес-правил по умолчанию)
py -m vira

# С указанием порта или режима LLM-объяснений (требуется OPENAI_API_KEY)
py -m vira --port 8080 --agent-mode llm
```

## Приёмочные и E2E-тесты

```bash
# Полный прогон приёмочных тестов (UC-03, UC-01, Q-02, границы 45%/10%, AC-03.4, Guardrail, MCP, HTTP API, Playwright E2E)
py -m unittest discover -s tests -v

# Регрессионный прогон базового прототипа
py -m unittest prototype/test_auditor.py -v
```

## Границы первой поставки

- Реальная торговля, авторизация в ЛК брокера и численный ML-прогноз цен (`ML-01`) не включены в веб-демо по условиям брифа.
- Открытые организационные/продуктовые вопросы из `VIRA-Передача-в-разработку.md` (`Q-02a`, `Q-04a`, `Q-05a`, критерии старта `ML-01`) вынесены в конфигурацию без хардкода в интерфейсе.
